# Current security status

Passwords are hashed with Argon2. Access tokens are tied to a database session and become invalid when that session is rotated or revoked. Refresh tokens are random, hashed in storage, rotated on use, and revocable. Evaluation workers use short-lived signed tokens limited to search for the active run’s knowledge base and lease. Owner filtering is applied to knowledge bases, documents, chunks, search and conversations. Uploaded filenames are not used as paths; generated UUID keys identify stored files. Limits and basic signature checks are applied, and DOCX uncompressed size is bounded. Retrieved text is treated as untrusted in prompts; no tools or secret material are supplied to the model.

This is not a security audit. The authentication limiter is in-process and per IP; it is not shared between workers or durable across restarts. Distributed rate limiting, CSRF-safe browser session architecture for persistent login, complete file deletion, resource isolation for parsers, more extensive malformed document and prompt injection tests, and production secret and network controls remain to be implemented. Citation validation only checks that cited IDs were in the context; it does not establish that a claim follows from the cited excerpt. The local frontend keeps tokens in memory, so a reload signs the user out. Do not expose the development server to the internet.
